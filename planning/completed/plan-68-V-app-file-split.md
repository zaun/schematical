# plan-68-V: App — the over-limit app files other than the document

Last updated: 2026-11-25
Effort: large (3h–1d)
Depends on: plan-68-U

Six app sources and one test file are over 1000 code lines besides
`SchematicModel.swift` (which letters B–F took apart). Each is split at the
seams it already has — separate types, `MARK:` sections, or an extension of
one type per job — and the DXF test fixtures, which are generated data
written as Swift string literals, become fixture files. Behavior is
unchanged; the scoped test classes of each area prove it.

Prerequisites: plan-68-A's table, and plan-68-U complete (`grep -c '\.py'
scripts/coverage-ratchet.tsv` → 0).

References:

- `schematical/schematical/Backend/PartCatalog.swift`,
  `Document/SchematicFile.swift`, `Canvas/SchematicCanvasView.swift`,
  `Canvas/PCBSidebarView.swift`, `Canvas/PCBCanvasView.swift`,
  `Automation/AutomationSchematic.swift`; `schematicalTests/DXFFixtures.swift`
  and its generator `planning/plan-65-data/make_fixtures.py`;
  `schematicalTests/FixtureSupport.swift` (`Fixture.directory`: fixtures read
  from `schematicalTests/Fixtures/` by `#filePath`).
- The app target uses file-system-synchronized groups (`grep -c
  FileSystemSynchronized schematical/schematical.xcodeproj/project.pbxproj`
  → 5): a new `.swift` file in a folder is compiled with no project edit.

## 1. Goal

- The seven files are split per § 3; every resulting file is at or under 800
  code lines.
- The test classes named in each phase pass; the app builds; the size
  ratchet's seven rows are gone, and with them the last rows of the file
  (the backend letters G–J removed theirs, plan-68-T removed
  `datasheet-edit.js`, plan-68-F `SchematicModel.swift`).

### Non-goals

- No behavior, API or file-format change. A `private` member that a moved
  piece still needs becomes `internal` (these are views, value types and
  extensions, not the document's stored state; letters D–F forbade that move
  for `SchematicDocument`'s storage).
- `DXFFixtures`'s public shape (`DXFFixtures.chainBoard` …,
  `DXFFixtures.expectedJSON`) stays, so no DXF test changes.
