# SC18IS604 SPI to I²C-bus bridge

## Description

An interface between a host's SPI port and an I²C bus. The host talks
to the SC18IS604 as an SPI slave (mode 3, up to 1.2 MHz); the
SC18IS604 is a single I²C-bus controller (transmitter or receiver,
up to 375 kHz) and handles all I²C-bus sequences, protocol, arbitration
and timing. It has 255-byte transmit and receive buffers, five GPIO
pins (four configurable), an active-low open-drain interrupt output,
an internal oscillator and a deep power-down mode woken by !{CS}.
Supply 1.71 V to 3.6 V; I/O pins are 5 V tolerant except MISO;
–40 °C to 105 °C.

It replaces the SC18IS600 except for: a new pinout; 255-byte instead of
96-byte buffers; five GPIOs instead of six, with no quasi-bidirectional
mode; 1.71 V instead of 2.4 V minimum supply; –40 °C to 105 °C instead
of 85 °C; and the part sits rotated 180° in the tape pocket (pin 1 in
quadrant 1).

## Functional description

Block diagram: the SPI slave and the I²C-bus controller share the
transmit and receive buffers; control logic, the interrupt logic, the
GPIO block and an on-chip RC oscillator complete the part.

### SPI

SPI mode 3 (CPOL = 1, CPHA = 1), MSB first by default, up to 1.2 MHz.
!{CS} selects the part; SCLK, MOSI and MISO may be shared with other SPI
slaves. Every transaction starts with a command byte (see
[registers and commands](#registers)).

### I²C bus

A byte-oriented I²C-bus controller for transfers up to 400 kHz
(I2CClk sets the clock, 375 kHz at most). SDA and SCL need pull-ups.
SCL and SDA do not have glitch suppression circuits. Source conflict:
the I²C-bus timing table still lists t~SP~, the pulse width of spikes
that must be suppressed by the input filter (50 ns). The source doesn't
say which applies.

### GPIO configurations

- **Input-only:** Schmitt-trigger input with glitch suppression.
- **Push-pull:** strong pull-down, and a strong continuous pull-up while
  the pin latch holds 1. Use where more source current is needed.
- **Open-drain:** only the pull-down is driven, while the pin latch holds
  0; an external pull-up is needed. The pin is pseudo open-drain: it
  can't be pulled above V~DD~, and it is not 5 V tolerant while V~DD~ is
  grounded.

Every configuration keeps the Schmitt-trigger input with glitch
suppression, so reading IOState returns the pin level in every mode.

### Deep power-down

The power-down command (0x30 0x5A 0xA5) stops the internal oscillator;
the part then ignores SPI messages. Any other byte sequence is ignored.
Raise !{CS} after the command; a later falling edge of !{CS} wakes the
part, and !{CS} then selects it again as usual.

### I2CClock (0x02)

```equation
f~SCL~ = 15 000 000 Hz / (8 × I2CClock)
```

```table id=i2cclk caption="I²C-bus clock examples"
| I2CClock (decimal) | f~SCL~ |
|--:|---|
| 5 (minimum) | 375 kHz |
| 7 | 268 kHz |
| 9 | 208 kHz |
| 19 | 99 kHz |
| 255 (maximum) | 7.4 kHz |
```

### I2CTO (0x03)

```table id=i2cto caption="I2CTO bits"
| Bit | Name | Description |
|---|---|---|
| 7:1 | TO[7:1] | Timeout value |
| 0 | TE | Timeout enable: 0 = disabled, 1 = enabled |
```

The longest time an I²C-bus transfer may take before the timeout
interrupt (approximate):

```equation
timeout = (I2CClock + 1) / 15 000 000 Hz × (1 + I2CTO[7:1]) × 512
```

After a lost arbitration the part sends a START again when the bus is
free, until the timeout is reached; then it interrupts on !{INT} with
status 0xF8.

### I2CStat (0x04)

```table id=i2cstat caption="I²C-bus status values"
| Value | Status | Interrupt |
|---|---|---|
| 0xF0 | Transaction completed successfully. Also the default status after reset [1]. | Yes; none after reset |
| 0xF1 | Target address not acknowledged: no target acknowledged the address of a read or write | Yes |
| 0xF2 | Data byte not acknowledged by the target | Yes |
| 0xF3 | Busy: an I²C-bus transaction is in progress; don't start another | No |
| 0xF8 | Timeout: a transaction took longer than I2CTO allows (failed arbitration, or a target holding SCL low) | Yes |
| 0xF9 | Invalid data count: the byte count of a read or write command is invalid | Yes |

[1] Source conflict: the register map gives I2CStat's reset value as 0x00.
```

### I2CAdr (0x05)

The part's own I²C-bus address, bits 7:1 (bit 7 is the first bit after
a START); bit 0 is unused, write 0. Not needed for operation, but set it
so it doesn't clash with a target on the bus.

### SPI commands

Every command is one !{CS}-low SPI transaction. Bytes after the command
byte are listed in order. Target addresses are A[7:1] plus the R/W bit
the part sets itself (the host's bit 0 is ignored).

```table id=commands caption="SPI commands"
| Command | Name | Host sends after the command byte | Result |
|---|---|---|---|
| 0x00 | Write N bytes to target | N (1–255), target address + W, data byte 1 … data byte N | Writes N bytes; !{INT} when done, status in I2CStat |
| 0x01 | Read N bytes from target | N (1–255), target address + R | Reads N bytes into the receive buffer; !{INT} when done. Read them with 0x06. |
| 0x02 | Read after write | N write bytes, M read bytes, target address + W, data byte 0 … N, target address + R | Writes N, then reads M bytes into the receive buffer; !{INT} when done |
| 0x03 | Write after write | N, M, target 1 address + W, N data bytes, target 2 address + W, M data bytes | Writes N bytes to target 1, then M bytes to target 2 |
| 0x06 | Read buffer | dummy bytes | Receive buffer data on MISO. A later 0x01 or 0x02 overwrites the buffer. |
| 0x18 | SPI configuration | 0x81 = LSB first, 0x42 = MSB first (default) | Sets the SPI bit order |
| 0x20 | Write register | register address, data byte | Writes one register, at once; no auto-increment |
| 0x21 | Read register | register address, dummy byte | Register data on MISO during the dummy byte; no auto-increment |
| 0x30 | Deep power-down | 0x5A, 0xA5 | Enters deep power-down (exact sequence only) |
| 0xFE | Read version | — | Puts "SC18IS604 1.0.0" plus a null (16 bytes) in the receive buffer and sets !{INT}; read with 0x06 |
```

## Application information

Typical I²C-bus use: SDA and SCL each with a pull-up R~PU~ to V~DD~,
shared with the other I²C-bus devices. Typical SPI use: the host's
SCLK, MOSI and MISO shared by several slaves, one !{CS} port pin per
slave.
