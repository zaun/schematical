## MAX6955

### What it is

I2C-compatible 2-wire LED driver for up to 16 digits of 7-segment, 8 digits of 14- or 16-segment, 128 discrete LEDs or a mix, with
five GPIO ports (open-drain outputs or inputs), a key-switch reader (up to 32 keys, n-key rollover, IRQ), a 104-character ASCII font for
14/16-segment digits, a hexadecimal font for 7-segment digits, per-segment blink between two RAM planes P0 and P1, 16-step digital
intensity (global or per digit), scan limit, shutdown and display test (`max6955` p.1, p.6). The SPI version is the MAX6954 (p.1; not
in this library).

### Packages, orderable parts, supply

- Ordering table (p.1): **MAX6955AAX+** 36 SSOP, **MAX6955ATL+** 40 TQFN-EP; temperature range -40 to +125 C both. (The `+T`
  tape-and-reel names of the same parts are not in the table.) No part is flagged obsolete by the sheet.
- Package codes (p.39): 36 SSOP A36-2, outline 21-0040, land pattern 90-0098; 40 TQFN-EP T4066+5, outline 21-0141, land pattern 90-0055.
  **The sheet prints only these codes, no drawing**, so no footprint can be drawn from it (the MAX6957 sheet gives A36-4 / 21-0040 / 90-0098 and T4066+5 / 21-0141 / 90-0055, again without drawings; analog.com was unreachable). Footprints are reported as missing.
- Supply V+: 2.7 V to 5.5 V (p.2 "Operating Supply Voltage V+ 2.7 5.5"); absolute maximum 6 V on V+ and on SCL/SDA/AD0/AD1 (p.2).
  Logic inputs VIH 0.7 x V+, VIL 0.3 x V+ on SDA, SCL, AD0, AD1 and the ports (p.3). Shutdown supply 10 uA typ, 35 uA max at +25 C
  (p.2). Operating current 22 mA typ all segments on (p.2).
- Model: `vcc` [2.7, 5.5]; `analog` ISET and OSC (the segment-current resistor and the RC oscillator capacitor / external clock).

### Bus (p.6-10)

- Slave receiver and transmitter, 400 kbit/s (p.1, p.4). 7-bit address `110 A3 A2 A1 A0` (p.7 "The first 3 bits ... are always 110"),
  A3 A2 from AD1 and A1 A0 from AD0, each GND = 00, V+ = 01, SDA = 10, SCL = 11 (p.10 Table 5): the address is 0x60 + 4 x AD1 + AD0 with
  those codes: AD1 on GND gives 0x60-0x63, on V+ 0x64-0x67, on SDA 0x68-0x6B, on SCL 0x6C-0x6F, and within a row AD0 on GND, V+, SDA, SCL
  gives +0, +1, +2, +3. Model: `address ["AD0", "AD1"]`, `table` [0x60, 0x61, 0x63, 0x62, 0x64, 0x65, 0x67,
  0x66, 0x6C, 0x6D, 0x6F, 0x6E, 0x68, 0x69, 0x6B, 0x6A] (the engine's tie digits are GND 0, V+ 1, SCL 2, SDA 3: the SDA and SCL entries swap).
- Write (p.8 Figures 7-9): START, address + W, command byte, then 1 or more data bytes; if a STOP follows the command byte it is only
  stored. The command byte is the register address, **bit 7 is a don't care** (Table 7 column D15 = X). Multiple data bytes go to
  consecutive registers: the command address auto-increments after each byte (p.10 Table 6): x0000000-x0001100 and x0001111-x1111110
  increment, x0001101 is factory reserved ("do not write this register"), x1111111 stays.
- Read (p.10): write the command byte (STOP, or a repeated START in multi-master systems), then a read transfer returns consecutive
  registers from the stored command byte, auto-incrementing; a NACK or STOP halts it. The stored command byte survives the STOP.
- Model: one `pointer` command per register range with `increment` 1; reads are `"read": "pointer"`.

### Scan timing (p.12, p.17 Figure 10, p.18-19)

`fOSC` 1-8 MHz (internal oscillator with RSET = 56 kOhm, CSET = 22 pF: 4 MHz typ, p.2). With OSC = 4 MHz each digit is enabled for
200 us, a cycle around 8 digits lasts 1.6 ms (Figure 10: "ONE COMPLETE 1.6ms MULTIPLEX CYCLE AROUND 8 DIGITS"); minimum interdigit
blanking 12.5 us. Blink (Table 19 p.26): "Slow blinking. Segments blink on for 1s, off for 1s with fOSC = 4MHz", fast on 0.5 s, off 0.5 s;
the electrical table (p.2) lists the slow and fast blink periods as 1 s and 0.5 s with RSET = 56 kOhm, CSET = 22 pF, V+ = 3.3 V. The oscillator is stopped in shutdown (p.12). Key scan: 25.6 ms cycle, each key tested twice 12.8 ms apart
(p.16, Figure 12).

### Digit and segment outputs: the pin multiplexing (Tables 2-4, 38-41) - NOT MODELED

The eight common-cathode outputs are O0-O7 (CC0-CC7), and the same pins are segment (anode) outputs in the periods in which another
cathode is active. 19 outputs O0-O18 form 4 *slots*; slot s (s = 0-3) owns cathode pins C0 = O(2s) and C1 = O(2s+1) and the periods of digits
2s and 2s+1. The digit-type bit pair (bit of CC(2s+1), bit of CC(2s)) picks the column of Tables 38-41 (read from the drawings of pp. 32-35):

In period k (cathode CCk = pin O_k active low) the other 17 pins - all of O0-O18 except C0 and C1 of k's slot, in ascending order - carry the
segment list below; the slot's other cathode pin is not used ("-", high impedance), and a pin marked "-" in the list is unused:

| list | 17 entries in pin order |
|---|---|
| L16 (16-segment digit, Table 2) | a1 a2 b c d1 d2 e f g1 g2 h i j k l m dp |
| L7 (a pair of 7-segment digits, Table 4) | 1a - 1b 1c 1d 1dp 1e 1f 1g 2a 2b 2c 2d 2e 2f 2g 2dp |
| L14 (14-segment digit, Table 3) | a - b c d - e f g1 g2 h i j k l m dp |

Which list a period uses (identical in all four slot tables, 38 CC0/CC1, 39 CC2/CC3, 40 CC4/CC5, 41 CC6/CC7; bit pair = (CC(2s+1), CC(2s))):

| bits | CC(2s) period | CC(2s+1) period |
|---|---|---|
| 0 0 | L16 (16-seg monocolor), or L7 (two 7-seg), or L16 for a bicolor 16-seg digit using both cathodes | same |
| 0 1 (CC(2s) = 14-seg) | L14 | L16 or L7 |
| 1 0 (CC(2s+1) = 14-seg) | L16 or L7 | L14 |
| 1 1 | L14 | L14, but the sheet prints j, k, l, m as "k, l, l, m" at O14-O17 in this column of all four tables (Tables 38-41 last column; the 14-segment columns elsewhere print j, k, l, m): a probable misprint |

**Unresolved by the sheet:** for a cathode whose type bit is 0 the sheet does not say what selects L16 (16-segment font) from L7 (7-segment
pair decoded or direct): the digit-type bit only tells 14-segment from the rest, the decode-mode register is described only for "pairs of
7-segment digits", and the register description for 16-segment digits never mentions it. Nothing in the text resolves it (p.10-12, p.22-24).
The pin tables, Tables 2-4 and the Typical Operating Circuits (p.36-38) all show the wiring only.

Segment data: the 14/16-segment font ROM (Tables 8 and 9 below) or the 7-segment decode / direct bits of the digit data of the active
plane. While the blink function is enabled (E = 1) the driver alternates P0 and P1 per blink phase (Table 21): a segment lit only in P0
is on during the first half of each blink period, only in P1 during the second half, both: always on, neither: off.
The test register D0 lights everything with duty 7/16 (p.19); shutdown stops the oscillator (p.12).

### GPIO and key scan (p.12, p.15-16, Tables 31-36)

Five ports P0-P4. Port configuration D4:D0: 0 = output (open-drain, so data 0 pulls low and data 1 releases), 1 = input. Reads of the GPIO data register
return the pin levels ("not debounced", p.12), D4 = P4 or the IRQ status. With key scanning on (D7:D5 != 000) P0-P3 become Key_A-Key_D
inputs with 75 uA pull-ups and P4 the IRQ output (Table 32).

### Model (what is in `leddriver.json`)

- bus `i2c` with AD0 / AD1 straps and the 16 addresses; `protocol` `fixed` frame with one `pointer` command per register range
  (command bit 7 ignored); read `pointer`; the 16 `0x60-0x6F` commands are 16-bit commands (command byte + one data byte) that store the byte in
  both planes.
- registers: every row of the table above that holds data. Plane P0 is the register space `p0` (0x20-0x2F), P1 the space `p1`
  (0x40-0x4F), both with reset 0x20 for digits 0-7 and 0x00 for 0a-7a. GPIO data is a latch (`LATCH`, space `g`) that drives the ports,
  and reads of command 0x05 return the pin levels (`RD`, filled by `pins.levels`; the `reads` alternative `PTR.G = 1`).
- `display`: driver `ports`: P0-P3 and P4/IRQ as open-drain ports with direction fields PORTCFG.P0..P4 (output while the bit is 0).
  The O0-O18 pins are never driven.

### Not modeled

- **The O0-O18 LED outputs**: no digit scan, no segments, no decode, no font, no test, no shutdown on the pins: the `digits`, `matrix`,
  `static` and `lcd` drivers cannot name one pin in two roles (cathode in one period, segment in another), cannot change the pin map per
  period from a register, and a device has one `display` driver (the ports driver is already used). See `engineNeeds`.
- Blink (E, B, T, P bits stored except P, T and R which read 0; no phase), intensity, segment current, scan limit (only stored).
- Configuration D5 R (global clear of both planes): the bit is not stored and does nothing.
- Key scan: Key_x pressed / debounced registers read 0, the masks are not stored, port bits D7:D5 do not change the ports (P0-P3 stay GPIO,
  IRQ is not driven).
- The 0x0C address: a write sets the digit type; the real read returns Key_A pressed; the model reads back the digit type.
- 0x60-0x6F writes are single data bytes only (no auto-increment through them) and the pointer is not set by them (the real part reads 0x00 there).
- A transfer past the last register of a range does not step to the next range (P0 -> 0x30, 0x2F -> 0x30, 0x17 -> 0x18); the pointer stays on the last
  register instead of moving to an unmapped address. 0x7F pointer lock is not modeled.
- Unspecified states: a floating input pin reads like a low one (engine).

## AS1115

### What it is

Compact 2-wire (I2C-compatible) LED driver for 64 single LEDs or 8 digits of 7-segment, key readback of 16 keys plus an interrupt, open and
shorted LED detection, Code-B or HEX decoding, 200 nA typ shutdown, digital and analog (RSET) brightness, software reset, optional external clock,
common-cathode displays (`as1115` p.3). There is no SPI interface in this part (the sheet's I2C-only; the feature register text mentions
"pin LD/CS" and "pin CLK" left over from the MAX7219 family, p.20).

### Packages, orderable parts, supply

- Ordering (p.26 Table 25): **AS1115-BSST** QSOP-24, **AS1115-BQFT** TQFN(4x4)-24, both "Tape and Reel", marking AS1115. No obsolete flag in the sheet.
- QSOP-24 drawing (p.24): JEDEC MO-137, body E1 3.91 BSC x D 8.66 BSC, e 0.635 BSC, E 6.00 BSC tip to tip, b 0.20-0.30, L 0.41-1.27 -> existing footprint
  `QSOP-24` (3.9 x 8.65, 0.635 pitch, E 6.00 mid) fits the outline.
- TQFN(4x4)-24 drawing (p.25): JEDEC MO-248, body D = E = 4.00 BSC, e 0.50 BSC, L 0.30-0.40, b 0.18-0.35, exposed pad D2 = E2 2.70-2.90, 24 terminals,
  6 per side. No existing footprint has this exposed pad: new footprint `TQFN-24-4X4-AMS` (rule R4 from the outline, in the result file).
- Supply VDD 2.7 V to 5.5 V (p.6 Table 3); absolute maximum 7 V (p.5). VIH 0.7 x VDD, VIL 0.3 x VDD (p.6 Table 4). Shutdown 0.2 uA typ, 2 uA max at +25 C;
  operating 0.35 mA typ (RSET open); segment current 41 mA typ at VDD = 5 V (p.6). Model `vcc` [2.7, 5.5], `analog` ISET.

### Bus (p.11-13)

- I2C slave, up to 1 MHz in the timing table (p.7 fSCL 1 MHz) and "high-speed mode 3.4 MHz" in the text (p.11).
- Address byte (p.12 Figure 20): predefined (factory) address **0000000** (7 bit), "the default slave address is factory-set to 0000000"; after the
  self-addressing command (register 0x2D, D0 = 1) the address is `00000 A1 A0` with A0 from KEYA together with SEGG and A1 from KEYA with SEGF (short = 0, open = 1);
  that command updates all connected AS1115 (p.12, p.17). The update is not modeled: the model has address 0000000 only.
- Write (p.13 Figure 22): START, address + W, command byte, data byte. The command byte is the register address (D15:D13 = 000 except the
  self-addressing register 0x2D = 001 01101). Figure 22 shows a single data byte; the sheet does not say whether a write auto-increments.
- Read (p.13 Figures 23-24): write the command byte (STOP), then read n bytes from the register, "Auto increment memory word address" after each byte;
  a NACK from the master stops it. Model: `pointer` with `increment` 1 for both (write auto-increment is an assumption).

### Scan timing (p.6, p.19)

8 digits scanned: display scan rate 0.48-0.96 kHz (Table 3 "fOSC"), 700 Hz typical (p.19: "When all 8 digits are to be displayed, the update frequency is typically
700Hz"; formula 10 x fOSC / (N + 2)). Model: 8 slots of 179 us (1 / (700 Hz x 8) = 178.6 us). Digits are common cathode: a digit is selected by pulling its DIG pin low, a lit
segment is driven high (Figure 1 p.3, p.4 pin table "sink current from the display common cathode" / "source current to the display").
Shutdown: "During shutdown mode the Digit-Registers maintain their data" (p.14); display test lights everything independently of shutdown (p.18).

### Model

`digits` driver: 8 digits DIG0-DIG7 active low, segments SEGA-SEGG, SEGDP active high, `segmentBits` [6, 5, 4, 3, 2, 1, 0, 7], rams the digit registers,
decode `codeB` per digit through `decodeField` DECODE.D0..D7, test TEST.DISP = 1, shutdown SHDN.RUN = 0 unless TEST.DISP = 1.

### Not modeled

- HEX decode (feature D2 = 1): the engine decodes one font per device; the model is fixed to Code-B (the power-up choice), so codes 10-15 read as Code-B (- E H L P blank) also with D2 = 1.
- Scan limit: every digit scans always (power-up scan limit 0 would scan digit 0 only).
- Intensity (global, per digit), RSET, blink (D4-D7), external clock (D0), the feature register reset on shutdown entry / exit (Shutdown D7), reg_res (D1: stored, no effect).
- Key scan: KEYA/KEYB read 0xFF, IRQ is never driven; open/short LED detection (diagnostic registers read 0, status bits read 0); self addressing (the address stays 0000000).
- Global intensity does not copy into the four per-digit registers.
