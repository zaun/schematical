## 1. ICM7211 (LCD) and ICM7212 (LED): 4-digit 7-segment decoder/drivers (`icm7211-icm7212`)

### 1.1 What they are
- Four-digit, seven-segment display decoder/drivers with input data latches and a BCD-to-segment ROM; "non-multiplexed" outputs: every segment of every digit has its own pin (28 segment pins) (p.1, p.8). 7211 drives a liquid crystal display (LCD), 7212 a common-anode LED display (p.1, p.8-9).
- Two fonts (p.10 Table 1): **hexadecimal** (7211, 7211M, 7212, 7212M) and **Code B** (suffix A: 7211A, 7211AM, 7212A, 7212AM). Suffix M = microprocessor input version, no suffix = multiplexed BCD input (p.1 table, p.9-10).
- Digit latches are the only state: BCD nibble in, decoded 7-segment out. Power-up latch contents are not specified by the sheet.

### 1.2 Output driver choice (decided from the sheet)
- **ICM7211**: the sheet's Figure 6 (p.8) shows one backplane (BP) square wave, 50 % duty, 0 to V+ (the backplane driver is an inverter fed by the last divider stage, p.8): "The segment driver output is the same as the backplane when the LCD segment is to be turned OFF, and is BACKPLANE (inverted) when ON". That is static (non-multiplexed, one backplane) drive: `lcddriver`, driver `lcd`, mode `static`, `backplanes ["BP"]`, 28 `segmentPins`; the RAM holds the already decoded 7 bits per digit (see 1.5). `frameUs` = half the backplane period: p.3 (Maxim Advantage table) gives fosc 19 kHz, fBP 150 Hz typ; p.8: "19 kHz ... divided by a 7 stage binary divider (/128) ... 150 Hz" -> 1/(2 x 150 Hz) = 3333 us. (The older table on p.2 gives 16 kHz and 125 Hz; the Advantage figures are used, they are the shipping Maxim spec.)
- **ICM7212**: "28 open drain constant current n-channel outputs" (p.9). A lit segment sinks current (common-anode LED), a dark segment is off: `leddriver`, driver `static`, `segmentActive low`, all 28 pins in `openDrain` (lit drives 0, dark is released). No scan, no timer.

### 1.3 Pins (p.1 DIP, p.4 DIP and PLCC for every variant, p.5 PLCC 7212)
Name collisions in the sheet's labels are renamed: data inputs B0-B3 -> `DIN0`-`DIN3` (they clash with segments B1-B4); the digit strobes "D1-D4" (digit select inputs of the multiplexed versions) -> `STB1`-`STB4` (they clash with segments D1-D4). Segment pins are the sheet's `<segment letter><digit>`: A1..G1 digit 1 ... A4..G4 digit 4. Roles: segments `output`; `BP` `inout` (backplane input/output, p.8); `OSC` and `BRT` `input` listed in `analog`; everything else `input`; `V+` power, `GND` ground. `CS1`/`CS2` are active low (p.4 overbars).

### 1.4 Bus (all variants: `parallel`, no read-back)
**Multiplexed BCD input** (7211, 7211A, 7212, 7212A; p.9, Figure 10 p.10): four BCD data lines `DIN3..DIN0` and four digit strobes `STB1..STB4`. A strobe taken high stores the (decoded) data in that digit's latch; "if the digit strobe is continuously held high, each transition of the backplane will cause another internal latch pulse, latching new segment data if the BCD data has changed" (p.9), so the latch is modeled transparent while the strobe is high. Truth table (Figure 10, p.10): strobes D1 D2 D3 D4 = 0000 no change; 0001 store in D4; 0010 D3; 0100 D2; 1000 D1; 1111 all four latches. Other combinations are not in the table and store nothing. Data setup -100 ns (strobe may rise before the data is valid), hold 200 ns, strobe width >= 1 us, inter-digit 2 us (p.2-3). Engine form: bus data pins `[STB1..STB4, DIN3..DIN0]` with no CS or WR ("every change of the data pins is a write"), commands `1000dddd` ... `1111dddd`.

**Microprocessor input** (suffix M; p.1, p.10 Figure 11): data `DIN3..DIN0`, digit select code `DS2 DS1`, two active-low chip selects `CS1`, `CS2`. "Data is entered into the input latches whenever either CS line goes low. When either CS line goes high an internal one-shot transfers the decoded 7-segment data into the digit latch" (p.10). Truth table (Figure 11): CS rising edge of either select while the other is low stores; DS2 DS1 = 00 -> D4, 01 -> D3, 10 -> D2, 11 -> D1. Nothing is stored while either select is high. Setup 100 ns, hold 0-10 ns, CS pulse >= 200 ns (p.2-3). Engine form: `parallel` bus, `cs` = CS1 (active 0), `wr` = CS2 (active 0), `address` `[DS2, DS1]`, `data` `[DIN3..DIN0]`; the engine decodes the transaction when either select is released, which is the datasheet's store.

### 1.5 Registers and decode
- 7212 (LED): registers `V1..V4` (4 bits each, the latched BCD nibble); `static` driver decodes `hex` (7212, 7212M) or `codeB` (7212A, 7212AM) with the engine's tables; microprocessor variants give `V4..V1` addresses 0..3 (DS2 DS1 code), so one command `aadddd` writes. Pins A1..G1 are group 1 ... A4..G4 group 4, in a..g order.
- 7211 (LCD): the `lcd` driver has no decode, so each digit is a 7-bit register `SEG1..SEG4` (bit 0 = a ... bit 6 = g) and every (strobe/select, nibble) command `set`s the register to the decoded segment mask as a constant (64 commands for M versions, 80 for the multiplexed ones: 16 nibbles x 4 digits, and for the multiplexed ones 16 x all-latches). Power-up: all segments off (the sheet gives no power-up value).
- Fonts (Table 1, p.10), segments a-g = bits 0-6: hex: 0 3F, 1 06, 2 5B, 3 4F, 4 66, 5 6D, 6 7D, 7 07, 8 7F, 9 6F, A 77, b 7C, C 39, d 5E, E 79, F 71. Code B: 0-9 as hex, 10 `-` 40 (g only), 11 `E` 79, 12 `H` 76, 13 `L` 38, 14 `P` 73, 15 blank 00. Checked glyph by glyph against the printed table (the 7 is a, b, c; 6 and 9 carry their bars; 1 is b, c).

### 1.7 Not modeled
- LCD: oscillator frequency change with an external capacitor or clock at OSC (p.8 Figure 7, p.11); backplane **slave mode** (OSC grounded makes BP an input, p.8, p.11 Figure 14): the model always drives BP, two chips sharing a backplane net run in the same phase; backplane rise/fall time, drive resistance (200 ohm BP, 2 kohm segments), annunciator tricks (p.11-12), segment leakage, DC offset.
- LED: brightness input BRT (analog, 0 V = display off, p.9 Figures 8-9), constant-current level (5-9 mA per segment, p.3), power dissipation limits.
- Internal strobe pulse timing (a strobe held high re-latches at each backplane/divider edge, p.9; modeled as transparent), tDS/tDH, one-shot width.
- Power-up latch contents.

## 2. ICM7244 and ICM7245: 8-character, 16-segment alphanumeric LED display decoder drivers

Both sheets describe the same function: 6-bit ASCII data written from a microprocessor into an 8 x 6 static memory, a 64-character ASCII font ROM to 16 segments + decimal point, multiplexed over 8 CHARacter (cathode) drivers, sequential or random entry (`icm7244-renesas` p.1, `icm7245-renesas` p.1). 7244: +5 V (4.75-5.25 V, p.4), segment drivers with 617 ohm typ. pull-ups (p.1, p.11 Figure 10), scan rate 400 Hz typ. 7245: +3.3 V (3.0-3.6 V, `icm7245-renesas` p.4), 136 ohm typ. pull-ups (p.1, p.11), 300 Hz scan typ. (p.4). Directly drives common-cathode LED displays.

### 2.1 Pins (44-lead MQFP; `icm7245-renesas` p.2 pin configuration and pin descriptions, `icm7244-renesas` p.2 and p.6 identical)
1 SEG d1, 2 SEG a1, 3 SEG a2, 4-9 D0-D5, 10 CS, 11 NC, 12 NC, 13 WR (active low), 14 CHAR8, 15 CHAR7, 16 CHAR6, 17 CHAR5, 18 VSS, 19 CHAR4, 20 CHAR3, 21 CHAR2, 22 NC, 23 NC, 24 CHAR1, 25 OSC/OFF, 26 A2/DISP FULL, 27 A1/CLR, 28 A0/SEN, 29 MODE, 30 SEG j, 31 SEG h, 32 DP, 33 SEG d2, 34 SEG f, 35 SEG i, 36 SEG b, 37 SEG g2, 38 SEG l, 39 VDD, 40 SEG m, 41 SEG e, 42 SEG g1, 43 SEG k, 44 SEG c. (Pin 38 prints "SEG I"; it is the lower centre vertical segment l: the segment set a1 a2 b c d1 d2 e f g1 g2 h i j k l m is 16.) Roles: segments, DP and CHAR1-8 `output`; A2/DISP FULL `inout`; D0-D5, CS, WR, A1/CLR, A0/SEN, MODE, OSC/OFF `input`; VDD power; VSS ground; OSC/OFF analog.

### 2.2 Segment layout (Figure 9 legend, p.10)
a1 a2 = top bar (left, right halves), f = upper left vertical, b = upper right vertical, h = upper left diagonal, i = upper centre vertical, j = upper right diagonal, g1 g2 = middle bar (left, right), e = lower left vertical, c = lower right vertical, m = lower left diagonal, l = lower centre vertical, k = lower right diagonal, d2 d1 = bottom bar (left, right), DP = decimal point. (In the library's `7seg` naming: h -> H, i -> J, j -> K, m -> N, l -> M, k -> L.)

### 2.3 Bus: write port only (no read-back)
- `CS` (high = selected, "from uP address decoder") and `WR` (low) are "immediately functionally ANDed": every action on an edge of WR with CS enabled happens on the equivalent last enabling or first disabling edge of either (p.11 "WR, CS"). Data D0-D5 is latched on the rising edge of WR and stored (p.11 "Data Entry"). Modeled: `parallel` bus, `cs` CS active 1, `wr` WR active 0, `data [D5..D0]`, `address [A2/DISP FULL, A1/CLR, A0/SEN]`.
- **MODE** is latched on the falling edge of WR (p.11): 0 = Random Access (RA), 1 = Sequential Access (SA). Modeled by copying the pin level into `CTRL.SA` (`pins.levels`); a MODE that changes outside a write pulse is therefore seen at once.
- **Random access** (MODE low): the address on A2 A1 A0 (A2 MSB) is latched on the falling edge of WR and the six data bits go to that character of the memory (p.2 pin descriptions, p.11). Characters 1-8 = addresses 0-7 (character 1 is the "left-most", p.1, scanned by CHAR1).
- **Sequential access** (MODE high): `A0/SEN` is latched on the falling edge of WR; with SEN high and DISP FULL low the entry is stored in the character the internal 3-bit counter points to (starting at character 1, address 000) and the counter increments on the rising edge of WR; with SEN low or DISP FULL high nothing happens (p.11-12, Figure 2 p.5). `A1/CLR` low is asynchronous: it clears the counter to 0 and the data memory to 100000 (blank = space, code 0x20) at any time (p.11). `A2/DISP FULL` is an output, high after 8 entries (display full) (p.2); tWDF 540 ns typ. DISP FULL becomes active right after the rising edge of WR (p.11 "Changing Modes"). Several chips cascade by chaining DISP FULL to the next chip's SEN (p.9 Figure 6).
- Changing modes: only on a falling edge of WR; A2 is an output until WR falls; from RA to SA A1/CLR must be high (p.11).
- Timing (not modeled): tWPI WR/CLR low >= 300 ns (7244, p.4) / 500 ns (7245, p.4), tDS 250 ns, tDH 0, tAS 40 / 100 ns, tAH 125 ns, tSEN 0, tWDF.

Engine form (the blocked devices in the result file): registers `CTRL.SA` (copied from MODE), `CNT.N` (0-8), `CH1..CH8` (6 bit, addresses 0-7, reset 32). Commands, first match wins: `x0xdddddd` when SA=1 -> clear (CH1..8 = 32, CNT.N = 0) [only while a write pulse is active; the asynchronous level clear is an engine need]; `xx1dddddd` when SA=1 and CNT.N = k (k = 0..7) -> CH(k+1) = d, CNT.N = k+1; `aaadddddd` when SA=0 -> write CH at address a. With CNT.N = 8 no command matches: the ninth entry is ignored. The power-up memory contents are not specified; reset 32 (blank) is used, as the sheet's CLR state.

### 2.4 Display scan (p.11-12 "Display Output", Figure 3 p.6 for 7245 / p.5 for 7244)
- Relaxation oscillator, nominal 200 kHz with the internal capacitor (p.11 OSC/OFF); pre-divided by 64, then by 8 in the multiplex counter: each CHARacter output lasts nominally about 300 us ("about 300us", p.12), exactly 64 / 200 kHz = 320 us, repeated every 8 x 320 = 2.56 ms (the sheet says nominally 2.5 ms, i.e. 400 Hz); the 7245 electrical table gives fDS = 300 Hz typ. at 3.3 V (p.4), the 7244 400 Hz (p.4). Modeled `scan.periodUs` 320 (the 200 kHz and /64 from p.11).
- Inter-character blanking of about 5 us (p.12, Figure 3) is not modeled (the scan has no gap).
- The CHARacter drivers are n-channel to VSS (rDS(on) about 4 ohm on the 7244, 7.4 ohm on the 7245, p.11 Figure 10): active level low, inactive = released ("effectively open circuits", p.12): modeled `digitActive low` with `openDrain` on CHAR1-8. The SEGment drivers are a switch to VDD through an internal pull-up resistor: a lit segment drives high (through 136 / 617 ohm), a dark one is open; modeled as driven high / driven low (`segmentActive high`), which an LED between SEG and CHAR cannot tell apart from open.
- Both CHARacter and SEGment outputs are disabled during WR operations in SA mode with SEN high and DISP FULL low (p.12): not modeled (the display keeps scanning).
- Standby: OSC/OFF low (below the relaxation oscillator's range) blanks the display, disables DISP FULL, clears the pre-divider and multiplex counter; memory is kept (p.1, p.11-12). Not modeled (engineNeeds).

### 2.5 Decode: 6-bit code to 16 segments + DP (Figure 9, p.10 of both sheets)
The six data bits are D5..D0 = ASCII bits 5..0: the table rows are D5 D4 = 00 (@ A-O), 01 (P-Z [ \ ] ^ _), 10 (space ! " # $ % & ' ( ) * + , - . /), 11 (0-9 : ; < = > ?), the columns D3..D0 = 0..F. The glyphs are 16-segment shapes with the decimal point part of a few glyphs (DP lit for `!`, `.` and the `:` position, which is drawn as a dot only). The decode is a mask ROM ("custom decode patterns by contacting Intersil", p.12), not user-programmable.

Method and confidence: the glyphs of `icm7245-renesas` p.10 were rasterised at 600 dpi, split into 64 cells, each segment's footprint measured on clean glyphs (8, X, Y, T) and tested against every cell (coverage >= 88 % with a +-7 px shift), the residue and a colour overlay checked for all 64 glyphs; three glyphs whose stroke is drawn as one long piece were set by eye (L = f e d1 d2; 4 = f b c g1 g2; 7 = a1 a2 b c). The 7244 sheet's Figure 9 (p.10) shows the same 64 characters in the same positions (compared by eye; its glyph artwork is drawn slightly differently), so one table serves both.
