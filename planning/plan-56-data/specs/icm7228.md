## Common to the family

- Supply: VDD 4 V to 6 V operating (2015 p.5 "Supply Voltage Range", TA 25 C and -40 to 85 C); 2 V minimum in power-down (RAM retained,
  2015 p.14); absolute maximum 6 V (p.5). Input voltage VSS-0.3 to VDD+0.3 (p.5). 5 V +-10 % is the test condition (p.5).
  Model: `vcc` [4, 6].
- Logic inputs: VIH 2.0 V, VIL 0.8 V (all inputs except pin 9 of the C/D, p.6). Digit drive 200 mA min (common anode) / 50 mA (common cathode),
  segment drive 25 mA / 12 mA typ (p.5): analog, not modeled.
- 8 digits x 7 segments + decimal point. The segments: a top, b upper right, c lower right, d bottom, e lower left, f upper left,
  g middle (Figure 11, p.13).
- Common anode (A, C): the digit driver is a P-channel pull-up to VDD (digit selected = VDD level), the segment driver an N-channel sink
  (segment lit = low) (Figure 12, p.15; text p.14). Common cathode (B, D): the digit driver is an N-channel sink (digit selected = low),
  the segment driver a P-channel source (segment lit = high) (Figure 13, p.15). Model: A/C `digitActive` high, `segmentActive` low;
  B/D `digitActive` low, `segmentActive` high.
- Multiplex: each digit is on about 320 us, scan rate about 390 Hz per digit (p.14; Figure 4 p.7 "320 us (TYP) free running (per digit)";
  fMUX 390 Hz typ, p.6). Interdigit blanking 10 us typ, 2 us min, with both digit and segment drivers off (p.14, p.6). The digit order
  is **D2, D5, D1, D7, D8, D6, D4, D3** (p.14). Model: `scan.periodUs` 320, `digitPins` in that order (the first slot, at time 0, is
  digit 2; the datasheet does not say which digit starts after power-up).
- Decoded characters (Table 5, 2015 p.13; the same on every version): input ID3-ID0 -> hexadecimal / Code B:
  0-9 both; 10 = A / `-`, 11 = b / E, 12 = C / H, 13 = d / L, 14 = E / P, 15 = F / blank.
- The decimal point is lit by a **low** level on ID7: "turned on by an input low level on ID7" (p.13, A/B text beside Table 6);
  C/D "ID7 (INPUT DP) Display Decimal Point Data Input, Negative True" (Table 3, p.10). Consistent with "blanked by writing Hex FF
  to all digits and selecting Code B" and "by No Decode and Hex 80" (p.14): ID7 = 1 is point off.
- Shutdown ("low power standby", typ 1 uA A/B, 2.5 uA C/D): the multiplex oscillator and the digit and segment drivers are turned off;
  input data can still be entered; RAM is retained down to 2 V (p.13-14). The outputs are high impedance (digit/segment leakage specs
  in shutdown, p.5); the model drives them to the inactive level instead.
- Bus timing (p.6, 25 C): WRITE low 200 ns min (tWL), high 850 ns min (tWH), mode setup 250 ns, data setup 250 ns, hold 0 ns, digit
  address setup 250 ns, hold 0 ns. WRITE is "rising edge sensitive" (Figures 1-3 p.7, Table 1 p.8 "written on rising edge of WRITE").
  Not checked by the model (a write is taken when WRITE rises with the pins as they are then).

## ICM7228A (common anode) and ICM7228B (common cathode): control register + sequential / single-digit update

function after the parenthesis is the control-word meaning.

Bus (2015 p.11-12, Figure 1 p.7, Figure 9 p.12). The chip looks like two I/O locations: MODE (address line A0) selects the control register
(high) or the display RAM (low); ID0-ID7 are the data; the data go in on the rising edge of WRITE. Model: `bus` parallel, `data`
ID7..ID0, `wr` WRITE active low, `address` [MODE]; a write is the bits MODE, ID7 ... ID0.

**Control word** (MODE = 1; Tables 1-2 pin descriptions p.8-10, p.11-12):

| Bit | Name | Meaning |
|---|---|---|
| ID7 | DATA COMING | 1: a sequential 8-digit update follows and the display is blanked; 0: no data coming (control-only update, or single-digit update) |
| ID6 | HEXA/CODE B | 1 hexadecimal decoding, 0 Code B |
| ID5 | DECODE | 1 No Decode, 0 Decode |
| ID4 | SHUTDOWN | 1 normal operation, 0 oscillator and display disabled |
| ID3 | RAM bank | with a decode format: 1 bank A, 0 bank B (which bank is written and displayed); no banks in No Decode |
| ID2-ID0 | digit address | with ID7 = 0: the digit of a following single-digit write, 000 digit 1 ... 111 digit 8 (Table 4 p.12) |

**Data write** (MODE = 0): 8 bits ID7-ID0.

- Sequential 8-digit update (p.12, Figure 2 p.7): after a control word with DATA COMING high the display is blanked and 8 successive
  writes fill digits 1 ... 8; after the 8th the display turns on again and further writes are ignored until the next control word.
  All 8 digits take the format of that control word (Decode/No Decode, hex/Code B; the bank ID3 chooses the bank written).
- Single-digit update (p.12): a control word with DATA COMING low (format in ID4-ID6, bank ID3, digit address ID2-ID0), then one
  write with MODE low puts ID0-ID7 into that digit's RAM. Each digit can be decoded or not independently ("each individual digit's data
  can be specified independently for being displayed in Decoded or No-Decode mode"); "whenever a control word is written, the specified
  decoding scheme [hex or Code B] will be applied to all those digits which selected to be displayed in Decoded mode" (p.12).
- Control-only update (p.11): one control word with DATA COMING low changes the format bits and, with a decode format, the displayed
  bank for all eight digits, without changing data.
- The decimal point does not depend on the bank: "a turned on decimal point will remain on for either bank" (p.11).

**Decode**: ID3-ID0 through Table 5 (above), the point from ID7 (low = lit). **No Decode** (Table 6, p.13): a high level lights the
segment: ID6 a, ID5 b, ID4 c, ID3 e, ID2 g, ID1 f, ID0 d, and ID7 the decimal point (low lights it).

Blanking by No Decode with Hex 80 in all digits (p.14).

### Model (what `leddriver.json` implements)

- `CTL` (12 bits, internal): `HEX` (ID6), `NODEC` (ID5), `RUN` (ID4), `BANK` (ID3), `ADDR` (ID2-0), `BLK` (display blanked by a sequential update), `ST` (0 single-digit, 1-8 the next sequential digit, 9 sequential update finished).
  `FLAGS` (8 bits): `D1`..`D8` = digit written with Decode. `DIG1`..`DIG8` (8 bits): `SEG` = ID6..ID0 as written, `DP` = 1 when the point is lit (ID7 low).
- Commands (frame fixed, one transaction per WRITE rising edge): the control word (`1 a b c d e fff`, sets all of `CTL`, `ST` = DATA COMING),
  and 64 data writes: digit k in {1..8} x {sequential at `ST` = k, single at `ST` = 0 and `ADDR` = k-1} x {ID7 = 0, 1} x {`NODEC` = 0, 1}:
  `DIGk.SEG` = ID6..0, `DIGk.DP` = not ID7, `FLAGS.Dk` = not `NODEC`; sequential also `ST` = k+1 (`ST` = 9 and `BLK` = 0 after digit 8).
  (The point polarity and the per-digit Decode flag are the reason for the 64 commands: the engine's `digits` driver lights a point on a
  set bit and takes the decode choice from a field, not from the control register at write time.)
- `display`: driver `digits`, 8 digits in the order 2,5,1,7,8,6,4,3, `decode` hex with `decodeField` = `FLAGS.Dk` per digit, raw
  `segmentBits` [6,5,4,0,3,1,2,7] (a, b, c, d, e, f, g, DP), `dpBit` 7, `scan` 320 us, `blank` `CTL.BLK=1`, `shutdown` `CTL.RUN=0`.
- Reset: every register 0, so **shut down until the first control word with ID4 high** (the datasheet gives no power-up state; RAM is
  random on silicon).
- Assumed, not stated by the sheet: further MODE-low writes after the first single-digit write go to the same digit until the next control word.

## ICM7228C (common anode) and ICM7228D (common cathode): digit address + data, no control register

Pins (2015 p.3, Table 3 p.10-11; D: 2002 p.2, Table 4 p.10-11). Outputs as the A (C) and B (D) columns above; inputs:

| Pin | Name |
|---|---|
| 5 | DA0 (digit address 0, LSB) |
| 6 | DA1 |
| 7 | ID7 (INPUT DP), negative true |
| 8 | WRITE |
| 9 | HEXA/CODE B/SHUTDOWN, three level (high hexadecimal, floating or mid-supply Code B, low shutdown) |
| 10 | DA2 (MSB) |
| 11 | ID1 |
| 12 | ID0 |
| 13 | ID2 |
| 14 | ID3 |

Bus (p.12, Figure 3 p.7, Figure 10 p.13): the 8 digits appear as 8 I/O locations: put the digit address on DA0-DA2 and the data on
ID0-ID3 and ID7, then pulse WRITE low; the data go in on the rising edge. No control register, no No Decode mode, no RAM banks (p.12).
Address to digit: the sheet has no table for the C/D; "DA0-DA2" with the A/B Table 4 mapping (000 digit 1 ... 111 digit 8) is assumed
(the Maxim ICM7218 sheet p.8, the pin-compatible original, says "the 8 digits of the ICM7218C/D are addressed as 8 contiguous bytes of RAM").
Decode: hexadecimal or Code B per pin 9 (Table 5 p.13), ID7 low lights the point; shutdown when pin 9 is low (p.13-14); pin 9 floating selects
Code B ("floating or driven to mid-supply", p.13; VINH 4.2 V, VINF 2.0-3.0 V, VINL 0.8 V, ZIN 50 kohm min, p.6).

### Model

- `DIG1`..`DIG8` (5 bits): `D` = ID3-ID0, `DP` = 1 when ID7 was low. Commands: 16 (digit address `kkk` x ID7), each `set` of `DIGk.D` and `DIGk.DP` (the same point-polarity reason).
  `bus` data [ID7, ID3, ID2, ID1, ID0], address [DA2, DA1, DA0], `wr` WRITE active low.
- `display`: `digits`, order 2,5,1,7,8,6,4,3, always decoded (hexadecimal font), `dpBit` 4, `scan` 320 us. Reset: every digit 0 (power-up RAM is undefined on silicon).
- **Pin 9 is not modeled** (no Code B, no shutdown): the engine's `pins.levels` reads a floating pin as 0, indistinguishable from low.

## Not modeled

- Code B decode (A/B ID6 low; C/D pin 9 floating): decoded digits always use the hexadecimal font.
- RAM banks A and B (A/B, ID3): a decoded digit has one nibble; bank select is stored in `CTL.BANK` and does nothing. Writes to either bank land in the same RAM.
- Pin 9 of the C/D (hexadecimal / Code B / shutdown): no effect.
- Interdigit blanking (10 us), digit/segment drive current and impedance, shutdown high impedance (outputs go to the inactive level), bus timing (setup, hold, pulse width), supply current, power-down retention.

## Engine needs (for a full model)

1. **Run-time decode choice**: `"decode": {"field": "CTL.HEX", "values": {"1": "hex", "0": "codeB"}}` in `digits`: the font follows the field's value (a value not listed uses the first entry). A/B: `CTL.HEX`.
2. **Three-level pin into a field**: a `pins.levels` entry with `"tristate": true`: the field is 0 while the pin is driven low, 1 while it floats (Z), 2 while it is driven high. C/D pin 9: `decode` {"field": "SEL.MODE", "values": {"2": "hex", "1": "codeB", "0": "codeB"}} and `"shutdown": "SEL.MODE=0"`.
3. **RAM bank** (A/B ID3): `"bank": {"field": "CTL.BANK", "ram": {"1": [8 names], "0": [8 names]}}` in `digits`: the scan reads the array chosen by the field (the protocol writes each bank's registers by its own `when CTL.BANK=v` commands); the point and the No Decode byte stay shared.
4. Optional: `"dpActive": 0` in `digits` (the point is lit while its bit is 0): would cut the A/B model from 65 to 33 commands and the C/D model from 16 to 8.
