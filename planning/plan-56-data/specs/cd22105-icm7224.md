## 1. CD22105 and CD22105A: four-digit LCD decoder-drivers (`cd22105-harris`)

### 1.1 What they are
- "Non-multiplexed, four-digit, seven-segment, liquid-crystal display decoder-drivers" with an on-board free-running oscillator that makes the backplane signal; no external components (p.1). Outputs: four sets of seven segment drives (28 pins) and a backplane input/output (pin 5) (p.1, p.3).
- Input: a four-bit data-input latch and a two-bit digit-select-code latch, with two chip-select inputs, for a microprocessor (p.1, block diagram p.3). The four-bit binary input is decoded by a programmable ROM into seven segments: hexadecimal for the **CD22105**, decimal ("Code B": `-`, E, H, L, P, blank) for the **CD22105A** (p.1, Table I p.5). "Pin-compatible with the ICM7211MIPL and ICM7211AMIPL, respectively" (p.1): the same part as the 7211M / 7211AM of plan-56-C.
- Package: 40-lead dual-in-line plastic, E suffix (p.1; outline p.8: A 0.120-0.250 in, D 2.000-2.090, E1 0.515-0.580, e 0.100 TP, eA 0.600 TP). Existing footprint `PDIP-40-600` (pins, pitch, 15.24 mm row span match; body 13.91 x 52.33 mm vs the drawing's 13.08-14.73 x 50.80-53.09).

### 1.2 Pins (p.1 terminal assignment, p.3 block diagram; the sheet's top view lists the left column 1-20 downwards, the right column 40-21)
1 VDD, 2 E1, 3 G1, 4 F1, 5 backplane input/output (BP), 6 A2, 7 B2, 8 C2, 9 D2, 10 E2, 11 G2, 12 F2, 13 A3, 14 B3, 15 C3, 16 D3, 17 E3, 18 G3, 19 F3, 20 A4, 21 B4, 22 C4, 23 D4, 24 E4, 25 G4, 26 F4, 27 B0, 28 B1, 29 B2, 30 B3 (the four data inputs), 31 DSC1, 32 DSC2 (digit select code), 33 CS1, 34 CS2 (chip selects), 35 VSS, 36 oscillator input, 37 A1, 38 B1, 39 C1, 40 D1. The block diagram (p.3) gives the same numbers per segment ("D1 segment outputs": 37 A1, 38 B1, 39 C1, 40 D1, 2 E1, 4 F1, 3 G1; "D4": 20 A4 ... 24 E4, 26 F4, 25 G4); G sits before F on every digit (the pinout column order is `... E, G, F`). The terminal figure (F4 beside pin 26, G4 beside pin 25) and the block diagram (`24 26 25` above E4 F4 G4) agree: 25 G4, 26 F4.
Names in the model: the data pins are `DIN0`-`DIN3` (the sheet's `B0`-`B3` clash with the segment names B1-B4), the digit select code `DSC1` (31), `DSC2` (32) (block diagram labels `DSC1`, `DSC2`; the pin list calls them D0/D1 which clash with D1), `CS1` (33), `CS2` (34) (active low: a write happens while they are low), `OSC` (36, analog), `VDD`, `VSS`. Roles: segments `output`, `BP` `inout`, everything else `input`.
Digit 1 is the least significant digit (the sheet: "D1 (LSD)", "D4 (MSD)", p.5).

### 1.3 Write protocol (p.5 truth tables, Fig. 4 timing p.4)
- Chip-select truth table (p.5): CS1, CS2 = 0, 0: "new inputs from the microprocessor are written into the input latches" (transparent); any other combination (0,1), (1,0), (1,1) after a write: "inputs are latched in the input latches, decoded, and passed through the selected (1 of 4) output latch to update the selected digit". Equivalent to the ICM7211M: the digit latch is loaded when either select rises, with both low before; nothing happens while a select stays high (the timing diagram p.4: one select held low, the other pulsed). Engine form: `parallel` bus, `cs` CS1 active 0, `wr` CS2 active 0, `address [DSC2, DSC1]`, `data [DIN3..DIN0]`, `frame` fixed; the engine decodes the transaction when either select is released.
- Digit selection truth table (p.5): (pin 31, pin 32) = (1,1) digit 1; (0,1) digit 2; (1,0) digit 3; (0,0) digit 4. As address value (DSC2 DSC1): 00 -> digit 4, 01 -> digit 3, 10 -> digit 2, 11 -> digit 1.
- Timing (p.2, typ., not modeled): chip-select active pulse width 100 ns, data setup 50 ns, hold 25 ns, inter-chip-select time 1 us.
- Table I (p.5), segments a-g = bits 0-6, CD22105 hexadecimal: 0 3F, 1 06, 2 5B, 3 4F, 4 66, 5 6D, 6 7D, 7 07, 8 7F, 9 6F, A 77, b 7C, C 39, d 5E, E 79, F 71. CD22105A decimal: 0-9 as above, 10 `-` 40, 11 E 79, 12 H 76, 13 L 38, 14 P 73, 15 blank 00. Confidence: the CD22105A column is clear; the hexadecimal column's code-12 glyph is printed as an `L`-like figure in the scan (the top bar sits on the row border and is lost, as the top bars of 7, 5, 6 are fused with the border too); the same RCA font in the identical pin-compatible ICM7211 sheet prints `C` (`icm7211-icm7212` Table 1), so C (a, d, e, f) is used. All other glyphs checked by eye at 600-900 dpi (6 and 9 carry their bars, 7 is a, b, c, 1 is b, c).
- Registers: `SEG1`..`SEG4` (7 bits, bit 0 = a ... bit 6 = g; reset 0 = all segments off, the sheet gives no power-up value); 64 commands (digit x nibble) set the register to the decoded mask, as the ICM7211M model does (the `lcd` driver has no decode).

### 1.4 Display drive
- Backplane: free-running oscillator 16 kHz typ. (p.2) divided by 128: 125 Hz typ. (p.2), "the backplane signal ... is common to all four-digit displays" (p.1). Fig. 6 (p.5): the backplane is a square wave, 64 oscillator cycles low and 64 high; segments that are OFF follow the backplane, segments that are ON are its inverse. That is static (one backplane) drive: `lcd` driver, `mode` static, `backplanes ["BP"]`, `frameUs` 4000 (64 cycles of 16 kHz = 4 ms: one alternation per frame).
- Supply: VDD 3 V min, 5 V typ., 6 V max (p.2 operating supply voltage range; absolute maximum 6.5 V, input voltage -0.3 V to VDD + 0.3 V, p.2). `vcc` [3, 6], `inputMax` 6. Input levels: VIH 3.5 V min, VIL 1.5 V max (VDD = 5 V, p.2).

### 1.5 Orderable parts (the sheet has no ordering table)
p.1: "supplied in the 40-lead dual-in-line plastic (E suffix) package"; the types are CD22105 and CD22105A. Names `CD22105E` and `CD22105AE`; DigiKey sells CD22105AE. The sheet is headed "Preliminary Data" and does not mark either type obsolete. Manufacturer Renesas Electronics (RCA -> Harris -> Intersil -> Renesas). No datasheet key: `renesas.com` hosts neither `cd22105-datasheet` nor `cd22105a-datasheet` (404; also `cd22105e`, `cd22105ae`, the product pages), so the parts carry a manufacturer and no `datasheet` (listed in the datasheets doc table when added).

### 1.6 Not modeled
Oscillator frequency change by an external capacitor on pin 36 (p.1, Fig. 3 p.3), slave mode (pin 36 at VSS makes BP an input, p.1; engineNeeds `lcd-slave-backplane`), the slave-device loading limit, rise/fall times, supply current, DC offset, the chip-select and data timing.

## 2. ICM7224 / ICM7225: 4-1/2 digit counter/decoder/drivers (`icm7224-icm7225-maxim`, `icm7224-icm7225-harris`)

### 2.1 What they are
- 4-1/2 digit up counters with decoder, display latch and display driver: the ICM7224 drives a (non-multiplexed) LCD directly, the ICM7225 has 29 constant-current open-drain LED outputs for a common-anode display (maxim p.1, p.6; harris p.1). Counter and control logic are identical (maxim p.6). Counting: DC to 25 MHz typ., 15 MHz guaranteed (maxim p.1, p.4; harris p.1, p.3), carry output for cascading, leading zero blanking in and out, STORE and RESET inputs.
- Counter (maxim p.6, harris p.6 "COUNTER SECTION"): a four-decade ripple counter with a Schmitt trigger on COUNT and a CARRY output; an extra D flip-flop clocked by CARRY holds the half digit ("1/2 digit"): "once the half-digit flip-flop has been clocked, it can only be reset (with the rest of the counter) by a negative level at RESET; however, the four decades continue to count in a normal fashion after the half-digit is set, and subsequent CARRY outputs will not be affected" (harris p.6). Maximum count 19999 (harris p.1). So: 9999 -> 10000 sets the half digit; the next 9999 wraps to 0000 with the half digit still set (display 10000).
- Table 1 / Table I control inputs (maxim p.5 pin descriptions, harris p.5 Table I; levels "V+ or floating" = inactive):
  | pin | input | function |
  |---|---|---|
  | 32 | COUNT | every negative-going transition clocks the counter, provided COUNT INHIBIT and RESET are high; 500 mV of hysteresis (maxim p.5) |
  | 31 | COUNT INHIBIT | low disables the counter ("a true inhibit": it disables the first divide-by-two without affecting the count; transitions on COUNT INHIBIT do not increment, harris p.6) |
  | 33 | RESET | low resets the four digits and the half-digit flip-flop and turns off the half-digit output; "Reset does not clear the data in the display latches unless STORE is low" (maxim p.6) |
  | 34 | STORE | low: the display latches are transparent (the counter is displayed); high or floating: the latches hold what is displayed (maxim p.5) |
  | 29 | LZB IN | high or floating: leading zero blanking enabled; low: zeros are displayed (maxim p.5, harris p.5). "The entire display will be blanked if this pin is high or floating, the count is 0000, and the half digit is reset." The half digit set also inhibits blanking (harris p.6: "When it is low, or the half-digit is set, leading zero blanking is inhibited") |
  | 30 | LZB OUT | high only when all four digits are blanked (maxim p.5: "goes high when all digits are blanked"; harris p.6: only when LZB IN is high and the half digit is not set); taken from the decoder, before the latch (harris p.2 functional diagram: the latch is after the decoder) |
  | 28 | CARRY | "goes high at count 6000 and goes low on the transition between count 9999 and count 10,000. The Carry output repeats this cycle every 10,000 counts" (maxim p.5): high from 6000 through 9999 of each 10000 counts; the negative edge clocks the next 4-digit device |
  | 27 | 1/2-digit | segment output for both segments of the half digit: "turns on when the count reaches 10,000 and is reset only by a low level on the Reset input" (maxim p.5); held by the latch (a "1/2-digit latch" in harris p.2) |
- Pull-ups: RESET, COUNT INHIBIT, LZB IN and STORE have internal 10 uA pull-ups (maxim p.3, harris p.3 "Input Pull-up Current" pins 29, 31, 33, 34), so they may be left open when a positive level is wanted; CARRY and LZB OUT are CMOS-compatible outputs (350 uA min each way, p.3).
- Font (maxim p.7 Fig. 5, harris p.7 Fig. 6), segments a-g = bits 0-6: 0 3F, 1 06, 2 5B, 3 4F, 4 66, 5 6D, 6 7D, 7 07, 8 7F, 9 6F; blank 00. The half digit is one pin driving both its segments.
- Latch and decoder: counter -> decoder (zero detection and blanking) -> 7-wide latch -> driver (harris p.2 Fig. 2): a blanked digit is latched blank.

### 2.2 Pins (maxim p.1 DIP top view; p.8 44-lead PLCC)
40-pin DIP: 1 V+, 2 E1, 3 G1, 4 F1, 5 BP (ICM7224) / BRT (ICM7225), 6 A2, 7 B2, 8 C2, 9 D2, 10 E2, 11 G2, 12 F2, 13 A3, 14 B3, 15 C3, 16 D3, 17 E3, 18 G3, 19 F3, 20 A4, 21 B4, 22 C4, 23 D4, 24 E4, 25 G4, 26 F4, 27 1/2-DIGIT, 28 CARRY, 29 LZB IN, 30 LZB OUT, 31 COUNT INHIBIT, 32 COUNT, 33 RESET, 34 STORE, 35 GND, 36 OSCILLATOR (ICM7224) / GND (ICM7225), 37 A1, 38 B1, 39 C1, 40 D1 (maxim p.1 note: pins 5 and 36 differ). The Harris figure agrees (harris p.1; its application figure 7 on p.7 prints LZB IN 30 / LZB OUT 29 but Table I p.5, the Maxim figure and the 44-pin figure give LZB IN 29, LZB OUT 30; the Maxim numbering is used).
44-lead PLCC (maxim p.8): 1 NC, 2 V+, 3 E1, 4 G1, 5 F1, 6 BP/BRT, 7 A2, 8 B2, 9 C2, 10 D2, 11 E2, 12 NC, 13 G2, 14 F2, 15 A3, 16 B3, 17 C3, 18 D3, 19 E3, 20 G3, 21 F3, 22 A4, 23 NC, 24 B4, 25 C4, 26 D4, 27 E4, 28 G4, 29 F4, 30 1/2-DIGIT, 31 CARRY, 32 LZB IN, 33 LZB OUT, 34 NC, 35 COUNT INHIBIT, 36 COUNT, 37 RESET, 38 STORE, 39 GND, 40 OSC (GND on the 7225), 41 A1, 42 B1, 43 C1, 44 D1.
Roles: segment pins `output`; `BP` `inout`; `BRT` `input` (analog); `OSC` `input` (analog); COUNT, COUNT INHIBIT, RESET, STORE, LZB IN `input` (the four overbarred names `activeLow`); CARRY (overbar in harris p.1/p.2 and maxim p.4 timing diagram) and LZB OUT `output`; V+ `power`; GND `ground`. The ICM7225 has two ground pins (35 and 36; the sheet: "The ICM7225 has two ground pins to handle the high LED drive currents", maxim p.5).
Supply: ICM7224 3-6 V (maxim p.3: V+ min 3, typ. 5, max 6; harris p.3 3-6 V), ICM7225 4-6 V (p.3); absolute maximum 6.5 V, inputs -0.3 V to V+ + 0.3 V (p.2); VIH 3 V min, VIL 1 V max (p.3); COUNT threshold 2 V typ. with 0.5 V hysteresis (p.3). `vcc` [3, 6] / [4, 6], `inputMax` 6.

### 2.3 Outputs
- **ICM7224** (`lcddriver`, driver `lcd`, mode static, `backplanes ["BP"]`): the internal oscillator is 19 kHz typ. divided by 128 -> backplane 150 Hz typ. (maxim p.3, p.6), a square wave, 50 % duty, 0 to V+, low impedance; the 29 segment drivers swing with the backplane: "drives an LCD segment in phase with the backplane to turn the segment off, and drives the segment 180 degrees out of phase with the backplane to turn the segment on" (maxim p.6-7; harris Fig. 4 p.7: 64 cycles + 64 cycles). `frameUs` 3333 (half of 6.67 ms). Segment pins A1..G1, A2..G2, A3..G3, A4..G4 and `1/2-DIGIT` (29, as the sheet's "29 segment drivers", maxim p.6); `ram` is `SEG1..SEG4` (7 bits each) and `SEGH`.
- **ICM7225** (`leddriver`, driver `ports`): "29 open drain N channel segment drivers, whose sink current varies from 0 to 9 mA as the voltage on BRT (pin 5) varies from ground to V+ (0 to 18 mA for pin 27, the half digit output)" (maxim p.7); the brightness input is analog. A lit segment sinks (drives 0), a dark one is released (Z): `ports` entries with `invert` true and all 29 pins in `openDrain`. CARRY and LZB OUT are two further `ports` entries (push-pull).

### 2.4 How the counter is expressed in the converter engine (what was checked)
The engine has no pin-triggered counter, but the unlatched parallel bus is one: "with neither `cs` nor `wr` every change of the data pins is a write" (docs § `bus`), so the five input pins are the bus. To make a write long enough to run a small program, the five pins are listed twice, as `address` and as `data`: one pin change is a **ten-bit write** (address bits COUNT, RESET, COUNT INHIBIT, STORE, LZB IN, then the data bits, the same five levels), and the `stream` frame matches up to six commands inside it, each command's `when` evaluated at its own boundary against the registers the previous command wrote (`ST.STG` is the program counter). The bits of one event are read at the same instant, so two inputs that change in the same simulation step cannot give a stale level (the first version used `pins.levels` fields for the conditions and lost a RESET that fell together with LZB IN; it is why STORE and LZB IN are loaded from the write's own bits).
- Stage 0 (3 bits: COUNT, RESET, COUNT INHIBIT, as literals): `a0x` RESET low clears `CNT1..CNT4`, `HALF`, `OUT.CARRY`; `011` with `ST.LASTC=1` (COUNT fell: COUNT was high at the last event, is low now) and the digits' values counts: 9 commands for digit 1, 9 each for the carry into digits 2, 3, 4, one for 9999 (digits to 0, `HALF` set, CARRY low); `axx` anything else only records the COUNT level in `ST.LASTC`. Because the level of COUNT is stored at every event, COUNT INHIBIT rising or falling while COUNT is low counts nothing, and a COUNT fall while INHIBIT is low is seen and not counted. CARRY is set when the carry into digit 4 makes it 6 or more (`OUT.CARRY`).
- Stage 1 (2 bits: STORE, LZB IN): copied into `PIN.STORE`, `PIN.LZB`.
- Stages 2-5 (one spare bit each, `x`): refresh digit 1, 2, 3, 4 (+ half digit) of the display registers `SEG1..SEG4`, `SEGH` from the counter, but only while `PIN.STORE` is 0 (transparent latch); STORE high leaves `SEGn` unchanged ("held" commands). The blank command of digit k fires first: LZB IN high, `HALF` 0 and `CNT4..CNTk` all 0 (digit k and every digit above are zero): `SEGk` = 0. Digit 1 blank means the count is 0000 and the whole display is blank; the same condition also sets `OUT.LZBOUT` (live, whatever STORE does). Otherwise `SEGk` = the font of `CNTk` (and `SEGH` = `HALF` at digit 4).
- Commands: 99 (stage 0: 39, stage 1: 1, digit 1: 13, digit 2: 12, digit 3: 12, digit 4 + half: 22). Generated by `scratchpad/g2/cdicm/gen.py` (not part of the repo).
- All five input pins must be driven: a pin that reads Z or X makes the ten-bit write invalid and nothing happens (the real chip pulls RESET, STORE, COUNT INHIBIT and LZB IN high internally): engineNeeds `pullups`. The first event after power-up only records the COUNT level (`ST.LASTC` resets to 0): a circuit whose first change is a COUNT fall with all pins already driven at time 0 misses that first count.
- Power-up: the sheet gives no initial state; the model starts with counter 0, half digit off, display latches blank (`SEG` 0), CARRY and LZB OUT low until the first event.

### 2.6 Not modeled
