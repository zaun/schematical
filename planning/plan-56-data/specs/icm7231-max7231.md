# ICM7231 / ICM7232 and MAX7231 / MAX7232 (+ MAX7233 / MAX7234, not modeled) (plan-56-F spec: icm7231-max7231)

Sources, all in `datasheets/lcd-drivers/`: `icm7231-icm7232-harris.pdf` (Harris File Number 3161, Dec 1993, 15-page scan; cited `icm7231-icm7232-harris p.N`), `max7231-max7234.pdf` (Maxim, (c) 1995, 16-page scan, no text layer; cited `max7231-max7234 p.N`) and `max7231-max7234-maxim-old.pdf` (the SAME Maxim sheet, same 16 pages, same content and (c) 1995 line, a poorer re-scan made in 2001: not a different revision; the main thread may drop it). Result file `scratchpad/g2/icm7231-max7231.json`, bench `scratchpad/g2/icm7231_max7231_test.c`. Citations are PDF pages. The engine used is main + `max695x-display.patch` + `pcf8576-lcd-mode-after-max695x.patch` (the `lcd` driver of those patches is NOT needed by these devices beyond what main has: `mode: "1:3"`, `ram`, `frameUs`, `enable`).

## 1. What the chips are
Triplexed (1/3 multiplexed) liquid-crystal display drivers with a built-in 6-bit-to-segment decoder ROM, input latches, an on-chip oscillator and the resistor string that makes the multiplex levels (harris p.1, p.3, p.8; max p.1, p.4-5).
- **ICM7231 / MAX7231**: 8 digits of 7 segments plus two independent annunciators per digit (16 annunciators); parallel entry: 4-bit data BD0-BD3, 2 annunciator bits AN1, AN2, 3-bit digit address A0-A2, strobe `CS` (harris p.1, p.6; max p.2, p.4).
- **ICM7232 / MAX7232**: 10 digits plus 20 annunciators; serial entry of 6 data bits + 4 address bits (harris p.6; max p.2, p.4).
- **MAX7233 / MAX7234**: 4 / 5 alphanumeric 18-segment characters (16 "flag" segments and 2 dots), 6-bit ASCII data, 2 / 3-bit address, parallel / serial (max p.1-2, p.4, p.12). NOT MODELED (section 9).
- Output codes (suffix letters): A = hexadecimal 7-segment, B = Code B, C = Code B with the C annunciator layout (max p.2 option table, p.12; harris p.6 Table of Features, p.12-13). The Harris sheet lists 7231BF, 7232AF, 7232BF, 7232CR; the Maxim sheet lists A, B, C of 7231 and 7232 and A, B of 7233 and 7234 (A = half-width numbers, B = full-width).
- Supply (both sheets): V+ 4.5-5.5 V; data retention guaranteed at 2 V; logic supply current 30 uA typ, 100 uA max with VDISP = 2 V; shutdown current 1 uA typ, 10 uA max (harris p.5; max p.3). Absolute maximum: supply 6.5 V; inputs VSS - 0.3 V to 6.5 V (they may be above V+); display voltage VSS - 0.3 to V+ + 0.3 V. Model: `vcc` [4.5, 5.5], `inputMax` 6.5. Input levels VIL 0.8 V, VIH 2.0 V.

## 2. Pins (40-lead DIP; Maxim also 44-lead PLCC)
Segment lines: each digit has three lines, named X, Y, Z in the Maxim sheet (max p.11 Figure 16, p.13 Figures 18-20) and in the Harris wiring figures (harris p.15 Figures 24, 17). Harris pin labels list the three cells of a line in the order COM1, COM2, COM3: Z = `b, c, an1`, Y = `a, g, d`, X = `f, e, an2` (harris p.2). The library names the pins `<digit>Z`, `<digit>Y`, `<digit>X` (`1Z` ... `8X`, `10X`), as Maxim does, for both makers' parts. Backplanes: Harris `BP1`-`BP3`, Maxim `COM1`-`COM3`. Supply: Harris `VDD` (40) / `VSS` (36), Maxim `V+` (40) / `GND` (36).

## 4. Display drive (modeled with the `lcd` driver, `mode: "1:3"`)
- Three common (backplane) lines and 24 (7231) / 30 (7232) segment lines. Backplane k is active in phase k; the common waveform has two polarity phases: phi1, phi2, phi3, phi1', phi2', phi3' (harris p.9 Figure 5; max p.11 Figure 14): "COM1 active during phi1 and phi1', COM2 during phi2, phi2', COM3 during phi3, phi3'". This is one pass of the three backplanes per polarity = the `lcd` driver's frame, alternating level on consecutive frames.
- Display frame rate fDISP 60 / 90 / 120 Hz min / typ / max (harris p.5; max p.3). One `lcd` frame = 1 / (2 x 90 Hz) = 5555.6 us: `frameUs` 5556, a slot 1852 us.
- A cell is a segment line crossing a common line; with the `lcd` driver a cell is lit when its RAM bit is 1: per digit the 9-bit register D<n> holds bit (3 x line + backplane - 1), line 0 = Z, 1 = Y, 2 = X.
- Cell map for A and B suffix (harris p.13 Figure 13, p.2 labels; max p.13 Figure 18): Z = b (BP1), c (BP2), an1 (BP3); Y = a, g, d; X = f (BP1), e (BP2), an2 (BP3).
- Cell map for C suffix (harris p.13 Table 3 and Figure 14; max p.12 Table 1, p.13 Figure 19): "LH annunciator on COM1 (top) (AN 2), RH annunciator on COM3 (bottom) (AN 1)"; the drawings put a, b on COM1 (with an2), f, g, c on COM2, e, d on COM3 (with an1): Z = b, c, an1 (same as A/B); Y = a, g, d (same); X = an2 (BP1), f (BP2), e (BP3). (The pin labels of the CR pinout print `f, e, an2` for X, the set, not the order.)
- Bias levels VH, VL from an on-chip string of three equal resistors (75 kohm typ; 40 kohm min) between V+ and VDISP; VP = V+ - VDISP is meant to be 3 x the liquid crystal threshold (harris p.5, p.9-10; max p.10-11): not modeled; the digital sim reads 0, 1 and Z.
- **VDISP shutdown**: "When open (or less than 1 V from V+) chip is shutdown; oscillator stops, all display pins to V+" (harris p.6; max p.4); data kept ("Low-Power Shutdown Mode Retains Data", harris p.1). Modeled: `pins.levels` copies the VDISP level into `CTRL.OFF`, `enable: "CTRL.OFF=0"`; VDISP reading 1 releases every backplane and segment pin (Z, the glass is dark; the real pins go to V+, which also leaves a glass dark) and the RAM stays. A VDISP that is open reads 0 here (levels read Z as 0), so an open VDISP is not shutdown (engineNeeds).

## 5. Parallel entry (ICM7231, MAX7231)
Data: `AN1` (30), `AN2` (31), `BD0`-`BD3` (32-35), address `A0`-`A2` (37-39), strobe `CS` (1). "Address and data bits are written into the input latches on the rising edge of the Chip Select input"; the rising edge triggers an internal one-shot that enables the address decoder and latches the decoded data into the addressed digit's output latches (harris p.6, p.11; max p.4, p.7). Timing: CS pulse width >= 500 ns, address/data setup 200 ns (Harris) / 350 ns (Maxim), hold 0, inter-chip-select >= 3 us / 3.5 us (harris p.5 Figure 1 p.7; max p.3 Figure 5 p.7): not enforced. `CS` has a special mid-level (about 3 V for several ms) test mode (harris p.6 note 3): not modeled.
Table 4 / Table 2 address: A2 A1 A0 = 000 .. 111 select D1 .. D8 (harris p.13 Table 2; max p.13 Table 4). Data codes (harris p.12 Table 1; max p.12 Table 2), segments lit, `a`-`g`:

| BD3-0 | hex (A) | Code B (B, C) |
|---|---|---|
| 0-9 | abcdef, bc, abdeg, abcdg, bcfg, acdfg, acdefg, abc, abcdefg, abcdfg | the same |
| 10 | abcefg (A) | g (`-`) |
| 11 | cdefg (b) | adefg (E) |
| 12 | adef (C) | bcefg (H) |
| 13 | bcdeg (d) | def (L) |
| 14 | adefg (E) | abefg (P) |
| 15 | aefg (F) | blank |

(7 is a, b, c; 6 and 9 carry their bars: checked on the printed glyphs at 260 dpi.) Annunciators (harris p.13 Table 3; max p.12 Table 1): AN1 / AN2 high = on, each its own cell: AN1 -> an1 (Z line, COM3), AN2 -> an2 (X line, COM3 for A and B, COM1 for C).
**Unresolved, flagged**: for the A and B versions both vendors' Table 3 / Table 1 pictures show AN1 = 1 lighting the LEFT-hand dot (".8") and Maxim's Figure 18 labels the left box AN1, but Harris's Figure 13 labels the left box an2 and the Harris pin labels put an1 on the b, c line (right-hand). For the C versions every source agrees (AN2 = left, COM1; AN1 = right, COM3). The model follows the pin labels for both makers (AN1 -> the `Z` line cell on COM3), which makes A, B and C consistent; if the printed pictures are right, the A and B annunciator cells of AN1 and AN2 are swapped. Only a real chip settles it.
Power-up: the sheets give no latch contents; the model starts dark (all RAM 0).
Model: `bus` parallel, `data` `[AN2, AN1, BD3, BD2, BD1, BD0]`, `address` `[A2, A1, A0]`, `wr` = pin `CS` active 0 and no `cs` (the engine's write is "CS and WR active, committed when either is released": CS rising), so one transaction is 3 address bits then 6 data bits; 128 commands (digit x code) `set` the three segment fields of `D<n>` to the decoded constants and `AN1`, `AN2` to the captured bits. `D<n>` is a 9-bit register with fields ZS [1:0], AN1 [2], YS [5:3], XS [7:6], AN2 [8] (C: ZS, AN1, YS, AN2 [6], XS [8:7]).

## 6. Serial entry (ICM7232, MAX7232)
Pins `DATA INPUT` (38), `DATA CLOCK` (1), `WRITE` (39, active low), `DATA ACCEPTED` (37, output). The shift register shifts on the rising edge of DATA CLOCK; the write order is AN1 (first), AN2, BD0, BD1, BD2, BD3, A0, A1, A2, A3 (last) (harris p.8 Figure 3 "ICM7232 WRITE ORDER", p.7 Figure 2; max p.8 Figure 6 and Figure 7). The word is 10 bits; "if only AN2 is to be turned on, nine bits are clocked in; if AN1 is to be turned on, all ten bits are used" (harris p.12; max p.7); with eight bits (BD0 first) both annunciators are off. DATA ACCEPTED goes low after the 8th clock and stays low through the 9th and 10th; the 11th clock resets the shift register and control logic ("Eleventh clock with no WRITE pulse resets SR + logic", Figure 2 p.7; max p.7). A WRITE pulse while DATA ACCEPTED is high only resets the shift register and control logic (no data is written); a WRITE pulse while DATA ACCEPTED is low decodes and stores the word in the addressed digit, then resets (harris p.6, p.11-12; max p.4, p.7). Procedure (harris p.12): while DATA ACCEPTED is high send a WRITE pulse first, clock in the bits, check DATA ACCEPTED, pulse WRITE. Table 2 / Table 4 address A3 A2 A1 A0 = 0000..1001 select D1..D10; 1010..1111 select NONE: "when an incorrect address is applied together with a WRITE pulse, none of the outputs will be changed" (harris p.13 Table 2, p.12; max p.13 Table 4). Fonts, annunciators, cells: as section 5. Timing (not enforced): data clock low >= 350 ns, setup 200 / 350 ns, hold 0, WRITE width >= 500 ns, WRITE to clock at initialization >= 1.5 us (Harris) / 4.0 us (Maxim), DATA ACCEPTED low delay 400 ns / 1 us max, high delay 3 us max, WRITE delay after last clock >= 350 ns (harris p.5; max p.3).
Model: `bus` spi, `cs` = `WRITE` with `csActive` 1 (the word is shifted while WRITE is high; the engine ends a transaction when WRITE goes low, so the word commits at the START of the WRITE pulse, up to 500 ns before the datasheet's rising edge; the rising edge begins the next, empty, transaction = the reset), `sclk` = DATA CLOCK, `mosi` = DATA INPUT, `mode` 3 (data taken on every rising clock edge, whatever the idle level), `protocol.frame` "fixed" with `align: "end"`: the commands are matched against the LAST bits clocked before the pulse. 480 commands in file order: the 10-bit ones (AN1 AN2 BD0-3 A0-3, 10 digits x 16 codes), then the 9-bit ones (AN2 ..., AN1 = 0), then the 8-bit ones (both annunciators 0); a word shorter than 8 bits matches none (nothing written, as when DATA ACCEPTED is high); an address of 10-15 matches none. Gaps: DATA ACCEPTED is never driven (engineNeeds); a word of more than 10 bits (the 11th clock resets the real chip) writes its last 10 bits (engineNeeds); a missing initial WRITE pulse is harmless here.

## 7. Registers (all devices)
`D1`..`D8` / `D10`: 9-bit display RAM of one digit, reset 0 (shown in the app's register window). `CTRL.OFF`: 1 bit, the level of VDISP. The `lcd` RAM stream is D1, D2, ... in order; `ramOrder` segment: segment pin g = 3 (digit - 1) + line, bit 3 g + backplane.

## 8. Not modeled
Display voltage levels, contrast, VDISP analog setting and temperature compensation; the oscillator and its power (only the fixed 90 Hz frame); the CS mid-level test mode; DATA ACCEPTED; the eleventh-clock reset; VDISP open as shutdown; every timing parameter of section 5-6; power-up latch contents (start dark).

## 9. MAX7233 / MAX7234 (18-segment alphanumeric): not added
Data: 6-bit ASCII D0-D5 (7233: pins 30-35; 7234: serial D0 first, then address A0-A2, write order D0 ... D5 A0 A1 A2; 9 bits; max p.8 Figure 8) selects one of 64 characters, decoded by a mask ROM to 18 cells on six segment lines per character (lines U, V, W, X, Y, Z) x COM1-COM3; address A0, A1 (4 characters, 7233; Table 5) or A0-A2 (5 characters, 7234) (max p.4, p.13 Table 5). 7233: pins CS1 (1), CS2 (39), D0-D5 (30-35), A0 (37), A1 (38) (the terminal table p.4 prints A1 as pin 3 and CS1 / CS2 as pins 39 / 1; the DIP pinout p.2 gives A1 = 38, CS1 = 1, CS2 = 39, A0 = 37: the pinout is followed; CS1 / CS2 are symmetric: both low loads, the rising edge of either latches). Table 3 (max p.12) gives the glyph of every code (D5 D4 = 00: `@ A-O`, 01: `P-Z [ \ ] ^ _`, 10: space and `! " # $ % & ' ( ) * + , - . /`, 11: digits `0-9` then `: ; < = > ?`; i.e. code = ASCII & 0x3F; the "A" suffix has half-width numbers, the "B" suffix full-width) and Figure 20 (p.13) the segment-to-cell wiring. The sheet has no way to load segment data directly, the only input is the 6-bit code. The glyph table is a 170 dpi scan and the cell wiring a hand drawing whose routing could not be read unambiguously, so no segment-level table was transcribed ("nothing may be guessed"). Lost: the whole 18-segment output of MAX7233 / 7234 (devices not added). What a transcription needs: for each of the 64 codes (x A, B) the set of lit (line, COM) cells; with it the device is the same shape as the 7231/7232 here (a 18-bit register per character, commands set it to constants) and needs no engine change.

## 10. Bench
`icm7231_max7231_test.c`: pinouts of every package (DIP, PLCC, the CR reversed one), every device (ICM7231B, ICM7232A/B/C, MAX7231A/B/C, MAX7232A/B/C) through the real bus: power-up dark, every digit x every code to the decoded RAM word and no other digit changes, annunciators, waveform on the pins (one backplane driven per slot, both levels, cell lit exactly when its bit is 1), VDISP shutdown and recovery, AC alternation and 5556 us frame, the GENERIC-LCD-8D-1:3 glass (wired Z to S<n>A, Y to S<n>B, X to S<n>C: the generic glass groups its cells differently from these chips, so a lit glass cell is compared with the RAM bit, not named as a segment), parallel latching on the rising edge of CS, serial 10 / 9 / 8-bit words, addresses 10-15, short words, a WRITE pulse that discards a partial word.
